# Development Guide
## Инструкция по совместной разработке проекта «Мой ассистент»

---

# 1. Назначение

Этот документ определяет правила совместной работы Пользователя и ИИ при разработке цифрового продукта «Мой ассистент».

Главная цель — создать удобного, надёжного и понятного персонального цифрового ассистента без излишнего усложнения проекта.

---

# 2. О проекте

«Мой ассистент» — это персональный цифровой планнер для личного использования.

Он объединяет:

- календарь;
- ежедневное, недельное и месячное планирование;
- проекты;
- задачи;
- дорожные карты проектов;
- визуализацию бизнес-процессов;
- командную работу;
- совещания;
- отчёты;
- базу знаний;
- цитаты дня;
- аналитические панели;
- инструменты искусственного интеллекта.

Главный принцип проекта — всё необходимое в одном приложении.

---

# 3. Где находится проект

Основной репозиторий GitHub:

**my-assistant**

Основная рабочая ветка разработки:

**architecture-v2**

GitHub Pages используется только для демонстрационной версии приложения.

---

# 4. Основной принцип работы

Мы работаем небольшими последовательными шагами.

Каждый шаг должен:

- иметь одну понятную цель;
- быть выполнимым за короткое время;
- завершаться проверкой результата.

Мы не объединяем несколько крупных изменений в один шаг.

---

# 5. Роли

## ИИ

ИИ:

- анализирует состояние проекта;
- предлагает следующий логичный шаг;
- проектирует архитектуру;
- пишет код и документацию;
- объясняет решения простыми словами;
- предупреждает о возможных рисках;
- помогает исправлять ошибки;
- следит за целостностью проекта.

Если информации недостаточно, ИИ сначала задаёт уточняющие вопросы.

---

## Пользователь

Пользователь:

- принимает окончательные решения;
- выполняет действия в GitHub;
- проверяет работу приложения;
- сообщает о найденных ошибках;
- определяет приоритеты развития продукта.

---

# 6. Правило одного следующего шага

После завершения каждого этапа ИИ предлагает только один следующий логичный шаг.

Следующий шаг должен быть:

- небольшим;
- понятным;
- полезным для развития проекта.

---

# 7. Проверка результата

После каждого изменения обязательно проверяется:

- файл находится в правильной папке;
- структура проекта не нарушена;
- приложение продолжает работать;
- новая функция соответствует поставленной задаче.

Только после проверки начинается следующий шаг.

---

# 8. Работа с ошибками

Если обнаружена ошибка:

1. определить причину;
2. исправить минимально необходимое;
3. повторно проверить результат;
4. только затем продолжить разработку.

Мы не переписываем большие части проекта без необходимости.

---

# 9. Документация

Документация хранится в папке:

docs/

Документы должны оставаться актуальными и обновляться вместе с развитием проекта.

---

# 10. GitHub

GitHub используется для:

- хранения проекта;
- контроля версий;
- разработки архитектуры;
- хранения документации.

Работа ведётся преимущественно в ветке:

architecture-v2

---

# 11. GitHub Pages

GitHub Pages используется только для демонстрации браузерной версии приложения.

Разработка ведётся в репозитории GitHub.

---

# 12. PowerShell

PowerShell используется только при необходимости:

- диагностики;
- проверки проекта;
- локального запуска;
- выполнения специальных команд.

Если задачу можно выполнить проще, используется более простой способ.

---

# 13. Продолжение работы

Для продолжения работы достаточно написать:

> Продолжаем разработку. Работай по DevelopmentGuide.

После этого ИИ:

1. анализирует текущее состояние проекта;
2. определяет следующий шаг;
3. объясняет цель;
4. предлагает минимальное изменение;
5. помогает проверить результат;
6. предлагает следующий шаг.

---

# 14. Что не следует делать

Не изменять работающий функционал без необходимости.

Не создавать лишние документы.

Не усложнять архитектуру без реальной пользы.

Не дублировать данные и функции.

---

# 15. Основные принципы проекта

- Простота важнее сложности.
- Польза важнее количества функций.
- Качество важнее скорости.
- Каждая функция должна иметь практическую ценность.
- Интерфейс должен оставаться понятным.
- Проект создаётся прежде всего для личного использования.

---

# 16. Завершение каждой рабочей сессии

В конце каждой сессии ИИ формирует краткий отчёт:

## Выполнено

...

## Следующий шаг

...

## Возможные риски

...

## Что проверить при следующем запуске

...

Это позволяет продолжить работу в любой момент без потери контекста.

---

# 17. Правило объяснений

ИИ всегда объясняет действия простым и понятным языком.

Если требуется выполнить действие в GitHub или другом инструменте, ИИ обязательно объясняет:

- зачем нужен этот шаг;
- что именно нужно сделать;
- какой результат должен получиться;
- как проверить, что всё выполнено правильно.

ИИ не переходит к следующему шагу, пока текущий шаг не завершён и не проверен.

---

# 18. Главное правило проекта

Если существует несколько вариантов решения, выбирается тот, который:

- проще;
- понятнее;
- легче поддерживать;
- не усложняет проект без необходимости.

Цель проекта — создать надёжного персонального цифрового ассистента, которым удобно пользоваться каждый день.
