# Data Model

## Модель данных проекта «Мой ассистент»

Этот документ описывает основные сущности данных приложения «Мой ассистент», их назначение и связи между ними.

---

## 1. Project — Проект

Проект объединяет связанные задачи и используется для организации работы.

Поля:

- `id` — уникальный идентификатор проекта
- `title` — название проекта
- `description` — описание проекта
- `status` — статус проекта
- `createdAt` — дата создания
- `updatedAt` — дата последнего изменения

Связи:

- один проект может содержать несколько задач

---

## 2. Task — Задача

Задача является основной единицей планирования в приложении.

Поля:

- `id` — уникальный идентификатор задачи
- `title` — название задачи
- `description` — описание
- `projectId` — идентификатор связанного проекта
- `date` — дата выполнения
- `startTime` — время начала
- `durationMinutes` — продолжительность в минутах
- `category` — категория задачи
- `sphere` — сфера
- `role` — роль пользователя
- `method` — метод выполнения
- `expectedResult` — ожидаемый результат
- `status` — статус задачи
- `createdAt` — дата создания
- `updatedAt` — дата изменения

Возможные статусы:

- `planned` — запланирована
- `in_progress` — выполняется
- `done` — выполнена
- `cancelled` — отменена

---

## 3. Meeting — Совещание

Сущность используется для хранения информации о встречах и совещаниях.

Поля:

- `id` — уникальный идентификатор
- `title` — название совещания
- `date` — дата
- `startTime` — время начала
- `durationMinutes` — продолжительность
- `projectId` — связанный проект
- `participants` — участники
- `result` — результат совещания
- `status` — статус

---

## 4. Habit — Привычка

Используется для регулярных действий пользователя, например спорта или заботы о здоровье.

Поля:

- `id` — уникальный идентификатор
- `title` — название привычки
- `sphere` — сфера жизни
- `schedule` — расписание
- `durationMinutes` — продолжительность
- `status` — состояние привычки

---

## 5. Связи между сущностями

Основные связи модели:

`Project 1 → N Task`

`Project 1 → N Meeting`

Задача может существовать без проекта.

Привычка может существовать независимо от проекта.

---

## 6. Хранение данных

В текущей версии приложения данные сохраняются локально в браузере пользователя.

Используется:

`localStorage`

В дальнейшем модель может быть перенесена в базу данных без изменения основной структуры сущностей.

---

## 7. Принципы модели

Модель данных строится по следующим принципам:

- каждая сущность имеет уникальный идентификатор;
- задачи и проекты разделены;
- задача может быть связана с проектом;
- поддерживаются задачи без проекта;
- данные о времени и продолжительности хранятся отдельно;
- модель допускает дальнейшее расширение приложения.
