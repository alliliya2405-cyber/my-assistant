# 1. Что это за проект

# 4. Что сделано на текущем этапе

Создан файл:

`core/storage/data-store.js`

Реализован минимальный публичный интерфейс Data Store v1:

- `MyAssistantDataStore.load()`;
- `MyAssistantDataStore.save(data)`;
- `MyAssistantDataStore.saveBackup(name, data)`;
- `MyAssistantDataStore.loadBackup(name)`;
- `MyAssistantDataStore.STORAGE_KEY`.

Модуль использует существующий основной ключ:

`myAssistantProFinal.v1`

Именованные резервные копии создаются как служебные ключи вида:

`myAssistantProFinal.v1.<name>`

Для существующего импорта сохраняется совместимый ключ:

`myAssistantProFinal.v1.beforeImport`

Модуль не подключён к `app.js`, поэтому текущая загрузка, сохранение и интерфейс приложения пока продолжают работать по прежней схеме.

---

# 5. Что проверено

Data Store проверен изолированно с тестовым объектом `localStorage`.

Проверено:

- `STORAGE_KEY` равен `myAssistantProFinal.v1`;
- при отсутствии данных `load()` возвращает `null`;
- `save(data)` сохраняет JSON без изменения структуры объекта;
- после сохранения `load()` возвращает эквивалентные данные;
- `saveBackup('beforeImport', data)` использует ключ `myAssistantProFinal.v1.beforeImport`;
- `loadBackup('beforeImport')` возвращает сохранённую резервную копию;
- повреждённый JSON не скрывается и приводит к ошибке, которую сможет обработать приложение.

Изолированный тест завершён успешно.

Работающий код `app.js`, пользовательские данные и текущий `localStorage` не изменялись.

---

# 6. Принятые решения

- Data Store остаётся тонким слоем физического хранения.
- Основной ключ `myAssistantProFinal.v1` не меняется.
- Формат JSON не меняется.
- Data Store не выполняет `normalize(...)` и не создаёт `sample()`.
- Data Store не содержит UI-логику и не скрывает ошибки чтения/записи.
- Пустое имя резервной копии считается ошибкой.
- Модуль публикуется как `window.MyAssistantDataStore` по тому же простому модульному подходу, который уже используется в `core/models/task.js`.
- Подключение Data Store к приложению выполняется отдельным следующим изменением.

# 9. Что пока не менять

Пока не менять:

- существующий работающий интерфейс;
- текущую функцию `persist(...)`;
- импорт и экспорт файлов;
- основной ключ `myAssistantProFinal.v1`;
- формат и содержимое существующего `localStorage`;
- функцию `normalize(...)`;
- стабильную модель задач `core/models/task.js`;
- пользовательские данные;
- способ хостинга приложения.

Не переводить все операции хранения на новый модуль одним большим изменением.

---

# 10. Что отложено на потом

После объединения модуля Data Store выполнять отдельно:

- подключение Data Store до `app.js`;
- перевод начальной загрузки на `DataStore.load()`;
- проверку чтения существующих данных;
- перевод `persist(...)` на `DataStore.save(state)`;
- перевод резервной копии импорта на Data Store;
- пользовательскую проверку сохранения, перезагрузки, экспорта и импорта;
- дальнейшие сервисы или Repository только при реальной необходимости;
- синхронизацию между устройствами;
- серверное хранение при появлении реальной потребности.
