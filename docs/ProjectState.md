# 1. Что это за проект

«Мой ассистент» — персональное веб-приложение для организации задач и дальнейшего развития функций личного цифрового ассистента.

Проект развивается небольшими законченными этапами без переписывания работающих частей без необходимости.

---

# 2. Стабильная версия

Стабильная контрольная версия находится в ветке `main`.

В `main` уже находятся Architecture v2, Data Model v1, Data Store Design v1 и минимальный модуль `core/storage/data-store.js`.

До текущей ветки приложение ещё читало начальное состояние напрямую из `localStorage`.

---

# 3. Текущая рабочая ветка

`data-store-load-v1`

Цель ветки — подключить Data Store только к начальному чтению состояния, не меняя сохранение, импорт, экспорт и пользовательские данные.

---

# 4. Что сделано на текущем этапе

В `index.html`:

- `core/storage/data-store.js` подключён до `app.js`;
- версия `app.js` в URL увеличена до `v=17`, чтобы браузер не использовал старый кэш после публикации.

В `app.js` изменена только начальная загрузка состояния:

- было прямое чтение и разбор `localStorage`;
- стало `MyAssistantDataStore.load()`;
- существующие `normalize(...)` и `sample()` сохранены;
- существующий `try/catch` сохранён, поэтому ошибка чтения по-прежнему приводит к безопасному начальному состоянию.

Функция `persist(...)`, импорт, экспорт и остальные прямые операции хранения не изменялись.

---

# 5. Что проверено

Проверен итоговый diff ветки относительно `main`.

До обновления документации в рабочем коде изменены только:

- `app.js` — 1 строка заменена;
- `index.html` — добавлено подключение Data Store и обновлена версия `app.js`.

Временный технический workflow, использованный только для точечного безопасного патча большого `app.js`, удалён и в итоговый PR не входит.

Дополнительно проверено:

- `MyAssistantDataStore.load()` вызывается после загрузки `data-store.js`;
- пустое хранилище сохраняет прежнее поведение через `normalize(null)`;
- повреждённый JSON сохраняет прежнее поведение через существующий `catch` и `sample()`;
- основной ключ хранения не изменён;
- `persist(...)` остаётся прежним и продолжает писать напрямую в тот же `localStorage`;
- формат данных и пользовательские данные не мигрируют и не очищаются.

---

# 6. Принятые решения

- Подключение Data Store выполняется постепенно.
- На этом шаге меняется только начальное чтение состояния.
- Сохранение через `persist(...)` пока не переводится на Data Store.
- Импорт и резервные копии пока не переводятся на Data Store.
- `normalize(...)`, `sample()`, модель задач и формат JSON не меняются.
- Для браузерной публикации используется новый cache-busting параметр `app.js?v=17`.
