# 1. Что это за проект

«Мой ассистент» — персональный цифровой планнер и цифровой ассистент для ежедневной работы с задачами, проектами, планированием, знаниями и личными областями жизни.

Проект развивается небольшими законченными этапами с обязательной проверкой и защитой пользовательских данных.

# 4. Принятые решения

- раздел «Проекты» дорабатывать по одному экрану и принимать каждый шаг отдельно;
- исправлять причину, а не маскировать симптом;
- данные и Data Store не менять для чисто визуальных этапов;
- не продолжать полировку уже удобного состояния без конкретной пользовательской проблемы;
- экран «Отчёты» должен показывать основной рабочий сценарий последовательно: персональные документы → сводный документ отдела → работа с готовым документом;
- ручной ввод, импорт, шаблоны и проверка настроек остаются доступными, но визуально не должны конкурировать с основным сценарием;
- форматы документов, генерацию Word, данные, правила интеграции и существующую бизнес-логику отчётов для визуального этапа не менять.

# 5. Над чем работаем сейчас

Текущий рабочий экран — **«Проекты → Отчёты»**.

По пользовательскому скриншоту проведён первичный аудит. Выбрана одна конкретная проблема: верхняя рабочая зона содержит много одинаково заметных действий и недостаточно ясно показывает последовательность работы.

В `main` выполнен небольшой визуальный этап **Reports Workflow Hierarchy v1**:

- персональные карточки сотрудников помечены как **«Шаг 1»**;
- сборка документа дошкольного отдела выделена как **«Шаг 2 · Сводный документ»**;
- блок выгрузки текущего готового документа помечен как **«Шаг 3 · Готовый документ»**;
- второстепенные ручные/служебные действия сделаны спокойнее;
- проверка раздела визуально отделена как контроль перед сборкой;
- уменьшены лишние интервалы без удаления функций;
- данные, форматы документов, генерация Word, импорт, интеграция персональных документов, обработчики и `app.js` не менялись.

Для публикации без старого кэша `styles/reports-personal-department-v1.css` подключён как `v=2`.

Рабочая версия: `main`.

# 7. Что пока не менять

Без отдельной продуктовой причины не менять:

- пользовательские данные;
- Data Store и формат `localStorage`;
- `core/models/task.js`;
- `app.js`;
- проектную и календарную бизнес-логику;
- автоматические связанные задачи;
- route id;
- завершённые экраны «Совещания», «Все проекты», «Команда» и «Ресурсная карта»;
- структуру данных отчётов;
- генерацию Word;
- правила импорта CSV/JSON;
- правила формирования сводного документа отдела;
- нижние карточки документов до визуальной проверки текущего этапа.
