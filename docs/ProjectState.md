# 1. Что это за проект

«Мой ассистент» — персональный цифровой планнер и цифровой ассистент для ежедневной работы с задачами, проектами, планированием, знаниями и личными областями жизни.

Проект развивается небольшими законченными этапами с обязательной проверкой и защитой пользовательских данных.

---

# 2. Стабильная версия

Стабильная контрольная версия находится в ветке `main`.

В `main` находятся Architecture v2, Data Model v1, Data Store v1, Application UX navigation v1 и обновлённый пользовательский интерфейс основных разделов приложения.

---

# 3. Что завершено и проверено

- основные экраны планирования доведены до единой спокойной визуальной системы;
- раздел «Жизнь» завершён и подтверждён пользователем;
- раздел «Знания» завершён и подтверждён пользователем;
- служебный блок «Ещё» прошёл автономный UI-проход без изменения бизнес-логики;
- раздел «Проекты» прошёл полный повторный UX/UI-проход через PR #39.

В Projects Section Polish v1 проработаны:

- «Все проекты» — усилена иерархия портфеля, поиска, проектных карточек и режима раскрытия;
- «Совещания» — карточки совещаний приведены к рабочей структуре: заголовок и метаданные → действия → проекты/вопросы/решения → задания → заметки;
- «Команда» — единый реестр организован в адаптивную сетку, проекты и поручения отделены друг от друга;
- «Ресурсная карта» — участники и их загрузка представлены компактными читаемыми карточками;
- «Отчёты» — командный центр и таблицы сотрудников упорядочены, большие таблицы получают горизонтальную прокрутку без лишней вертикальной вложенности;
- универсальный collapse адресно отключён на рабочих экранах «Совещания / Команда / Ресурсная карта / Отчёты» и не вмешивается в собственный механизм раскрытия проектных карточек.

При этом не менялись `app.js`, пользовательские данные, Data Store, модель задач и существующая проектная бизнес-логика.

---

# 4. Принятые решения

- исправлять причину, а не маскировать симптом;
- избегать вложенной вертикальной прокрутки там, где экран может расти в обычном потоке страницы;
- универсальный collapse не должен скрывать рабочий контент;
- собственный механизм раскрытия проектных карточек сохранять отдельно от универсального collapse;
- текст и содержимое важнее технических действий;
- опасные действия визуально отделять от обычных;
- данные и Data Store не менять для чисто визуальных этапов;
- пользователь не участвует в каждом промежуточном шаге: ИИ выполняет доступную разработку самостоятельно и показывает итоговый вариант.

# 7. Что пока не менять

Без отдельной продуктовой причины не менять:

- пользовательские данные;
- Data Store и формат `localStorage`;
- `core/models/task.js`;
- проектную и календарную бизнес-логику;
- автоматические связанные задачи;
- route id;
- существующие обработчики проектов, совещаний, поручений и отчётов;
- импорт и экспорт.
