# 1. Что это за проект

«Мой ассистент» — персональный цифровой планнер и цифровой ассистент для ежедневной работы с задачами, проектами, планированием, знаниями и личными областями жизни.

Проект развивается небольшими законченными этапами с обязательной проверкой и защитой пользовательских данных.

---

# 2. Стабильная версия

Стабильная контрольная версия находится в ветке `main`.

В `main` находятся:

- Architecture v2;
- единая модель задачи `core/models/task.js`;
- Data Model v1;
- Data Store v1 с чтением и обычным сохранением через `MyAssistantDataStore`;
- Application UX navigation v1;
- Главная / Сегодня v1;
- Design System v1 — task density;
- Task Card Unified v1 после Pull Request #10;
- документация UX и дизайн-системы в `docs/`.

---

# 3. Что завершено и проверено

Data Store проверен на реальных пользовательских данных: существующие и новые/изменённые задачи сохраняются после перезагрузки.

Application UX navigation v1 и Главная / Сегодня v1 опубликованы и визуально подтверждены пользователем.

Design System v1 — task density объединён с `main` через Pull Request #9. Карточки задач стали компактнее, уменьшены отступы и тени, улучшена визуальная иерархия.

На пользовательской проверке экрана «Задачи» обнаружен визуальный дефект: универсальная панель сворачивания создавала внутри каждой раскрытой задачи второй визуальный заголовок, из-за чего строка выглядела как две карточки.

Исправление Task Card Unified v1 выполнено в отдельной ветке `task-card-unified-v1` и объединено с `main` через Pull Request #10.

Исправлено:

- раскрытая задача теперь должна выглядеть как одна цельная карточка;
- дублирующий заголовок панели сворачивания скрыт в раскрытом состоянии;
- кнопка сворачивания стала компактным элементом слева;
- при реально свернутой задаче её заголовок остаётся видимым;
- действия «Изменить / Готово» и логика задач не менялись;
- `app.js`, Data Store, модель задачи и пользовательские данные не менялись;
- исправление изолировано в `styles/task-card-unified-v1.css`;
- `index.html` изменён только подключением этого CSS-файла;
- временные workflow и patch-скрипты удалены до Pull Request.

Pull Request #10 перед объединением имел `mergeable: true` и успешно объединён с `main`.

---

# 4. Принятые решения

- UX меняется постепенно без удаления существующих функций;
- дизайн-система развивается от плотности, читаемости и иерархии, а не от массовой перекраски;
- визуальные дефекты после пользовательской проверки исправляются до перехода к следующему этапу;
- route id, пользовательские данные, Data Store и бизнес-логика сохраняются, пока нет отдельной причины их менять;
- следующий крупный визуальный этап — верхняя панель и быстрые действия, но только после проверки Task Card Unified v1.

---

# 5. Над чем работаем сейчас

Task Card Unified v1 уже находится в `main`.

Активной рабочей ветки для следующего изменения пока нет.

Текущая контрольная задача — визуально проверить опубликованный экран «Задачи» после устранения дублирующей панели внутри карточки.

---

# 6. Следующее одно действие

**после публикации GitHub Pages открыть «Планирование → Задачи» и проверить одну раскрытую и одну свернутую задачу: раскрытая должна выглядеть как одна карточка без повторного заголовка, а свернутая — сохранять название и возможность развернуть её.**

Если проверка успешна, Task Card Unified v1 считается полностью проверенным.

Следующим отдельным этапом будет доработка верхней панели и быстрых действий.

Если обнаружена проблема, дальнейшая визуальная разработка останавливается и сначала исправляется эта проблема.

---

# 7. Что пока не менять

До пользовательской проверки Task Card Unified v1 не менять:

- пользовательские данные;
- Data Store и формат `localStorage`;
- `core/models/task.js`;
- route id;
- бизнес-логику задач, проектов и календарей;
- импорт и экспорт;
- другие экраны массовыми изменениями;
- способ хостинга.

---

# 8. Что отложено на потом

После успешной проверки:

- улучшить верхнюю панель и быстрые действия;
- распространить дизайн-систему на проекты и другие основные экраны;
- отдельно решить перенос импорта/экспорта из постоянного footer в настройки;
- при необходимости улучшить глобальный поиск и сервисное меню.

Отдельно по необходимости:

- перевод резервной копии импорта на Data Store;
- проверка импорта и восстановления;
- сервер и синхронизация между устройствами только при появлении реальной потребности.
