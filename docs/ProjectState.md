# 1. Что это за проект

«Мой ассистент» — персональное веб-приложение для организации задач и дальнейшего развития функций личного ассистента.

Проект уже является рабочим приложением и развивается постепенно, без переписывания работающих частей без необходимости.

---

# 2. Как устроен проект

Основное приложение находится в корне репозитория.

Основные файлы:

- `index.html` — интерфейс приложения;
- `app.js` — существующая логика приложения;
- `styles.css` — оформление;
- `core/` — новая архитектурная часть проекта;
- `docs/` — документация и контроль состояния проекта.

Основная модель задачи находится в:

`core/models/task.js`

Документация находится в:

`docs/`

# 4. Что проверено

После внедрения Architecture v2 проверено:

- приложение открывается;
- существующие задачи отображаются;
- новая задача создаётся;
- новая задача появляется в списке;
- основные элементы интерфейса продолжают работать;
- данные сохраняются локально.

Текущая версия в `main` считается стабильной контрольной версией.

---

# 5. Принятые решения

Проект развивается небольшими законченными этапами.

Каждое существенное архитектурное изменение выполняется в отдельной рабочей ветке.

После изменения необходимо:

1. проверить работу приложения;
2. обновить документацию;
3. объединить готовое изменение с `main` через Pull Request.

Работающая версия приложения не переписывается без отдельной причины.

Документы проекта используются как внешняя память разработки.

# 8. Что пока не менять

Пока не менять без отдельного решения:

- существующий работающий интерфейс;
- рабочую логику приложения, не относящуюся к текущему этапу;
- существующее локальное сохранение данных;
- стабильную модель задач `core/models/task.js`;
- структуру Architecture v2, уже объединённую с `main`.

Сначала проектируем следующий слой, затем изменяем код.

---

# 9. Что отложено на потом

После завершения текущего этапа можно рассматривать:

- единое хранилище данных приложения;
- постепенный перевод существующих разделов на единый слой данных;
- дальнейшее расширение модели данных;
- новые функции ассистента;
- синхронизацию данных между устройствами;
- другие улучшения после стабилизации архитектуры данных.

Эти пункты не являются текущей задачей.

---

# 10. Правило восстановления проекта в новом чате

Перед продолжением разработки необходимо сначала изучить:

1. `docs/DevelopmentGuide.md`
2. `docs/ProjectState.md`

Если текущая работа ведётся в отдельной ветке, также необходимо изучить документы и изменения этой ветки.

После этого определить:

- что уже сделано;
- что проверено;
- какая ветка является текущей;
- над чем идёт работа;
- какое одно действие является следующим;
- что пока нельзя менять.

Только после восстановления этой контрольной точки продолжать разработку.

---

# 11. Правило обновления состояния

После каждого значимого законченного результата необходимо обновлять `docs/ProjectState.md`.

В первую очередь обновлять:

- что сделано;
- что проверено;
- принятые решения;
- текущую работу;
- следующее одно действие;
- что пока не менять;
- отложенные задачи.

`ProjectState.md` должен описывать фактическое состояние проекта, а не планы, которые ещё не выполнены.
