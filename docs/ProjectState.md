# 1. Что это за проект

«Мой ассистент» — персональный цифровой планнер и цифровой ассистент для ежедневной работы с задачами, проектами, планированием, знаниями и личными областями жизни.

Проект развивается небольшими законченными этапами с обязательной проверкой и защитой пользовательских данных.

---

# 2. Стабильная версия

Стабильная контрольная версия находится в ветке `main`.

В `main` находятся Architecture v2, Data Model v1, Data Store v1, Application UX navigation v1 и обновлённый пользовательский интерфейс основных разделов приложения.

---

# 3. Что завершено и проверено

- основные экраны планирования доведены до единой спокойной визуальной системы;
- раздел «Жизнь» завершён и подтверждён пользователем;
- раздел «Знания» завершён и подтверждён пользователем;
- служебный блок «Ещё» прошёл автономный UI-проход без изменения бизнес-логики;
- раздел «Проекты» прошёл общий UX/UI-проход через PR #39;
- по обратной связи пользователя принято решение дальше дорабатывать раздел «Проекты» пошагово, начиная с «Совещаний».

Для «Проекты → Совещания» через PR #40 добавлен собственный механизм сворачивания карточек:

- каждая карточка может сворачиваться и разворачиваться независимо;
- в свернутом состоянии остаются название, дата, участники и основные действия;
- проекты, вопросы, решения, задания участникам и заметки скрываются;
- добавлены действия «Свернуть все / Развернуть все» для удобной работы с несколькими совещаниями;
- новые карточки автоматически получают тот же механизм после рендера;
- универсальный collapse по-прежнему не используется на экране совещаний.

При этом не менялись `app.js`, пользовательские данные, Data Store, модель задач и существующая логика совещаний.

---

# 4. Принятые решения

- раздел «Проекты» дорабатывать по одному экрану и принимать каждый шаг отдельно;
- исправлять причину, а не маскировать симптом;
- универсальный collapse не должен управлять сложными рабочими экранами;
- для совещаний использовать отдельное предметное сворачивание карточек;
- в свернутой карточке сохранять достаточно информации для быстрого выбора нужного совещания;
- данные и Data Store не менять для чисто визуальных и навигационных этапов.

# 7. Что пока не менять

Без отдельной продуктовой причины не менять:

- пользовательские данные;
- Data Store и формат `localStorage`;
- `core/models/task.js`;
- проектную и календарную бизнес-логику;
- автоматические связанные задачи;
- route id;
- существующие обработчики создания, редактирования, протокола, распознавания задач и удаления совещаний;
- остальные экраны раздела «Проекты» до завершения текущего шага «Совещания».

---

# 8. Что отложено на потом

После подтверждения сворачивания карточек продолжить пошаговую доработку экрана «Совещания», затем отдельно перейти к «Все проекты», «Команда», «Ресурсная карта» и «Отчёты».

Сервер и синхронизацию между устройствами рассматривать только при реальной потребности.
