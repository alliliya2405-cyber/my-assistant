# 1. Что это за проект

«Мой ассистент» — персональный цифровой планнер и цифровой ассистент для ежедневной работы с задачами, проектами, планированием, знаниями и личными областями жизни.

Проект развивается небольшими законченными этапами с обязательной визуальной проверкой и защитой пользовательских данных.

---

# 2. Стабильная версия

Стабильная контрольная версия находится в ветке `main`.

В `main` находятся Architecture v2, Data Model v1, Data Store v1, Application UX navigation v1, основные этапы дизайн-системы для Главной, задач, проектов и планирования, а также завершённые визуальные этапы раздела «Жизнь».

Последние подтверждённые этапы:

- Health Habit Cards v1 + Health Collapse Fix v1;
- Family Cards v1 + Family Layout Fix v1/v2;
- Education Cards v1 через PR #29;
- Leisure Cards v1 через PR #30 + Leisure Collapse Fix v1 через PR #31;
- Notes Cards v1 через PR #32.

---

# 3. Что завершено и проверено

Основные экраны «Главная», «Задачи», «Проекты», «Сегодня», «Неделя» и «Месяц» проверены пользователем на опубликованной версии.

Раздел «Жизнь» завершён и визуально подтверждён пользователем:

- «Здоровье» — привычки раскрыты сразу, ежедневное действие видно, лишний collapse устранён;
- «Семья» — текст записей читается нормальными строками, действия не сжимают содержимое;
- «Образование» — четыре раздела отображаются сбалансированной сеткой 2×2, карточки раскрыты и читаемы;
- «Досуг» — карточка отображается без лишней collapse-шапки и без глобальных кнопок «Свернуть все / Развернуть все».

При визуальных этапах раздела «Жизнь» пользовательские данные, Data Store и бизнес-логика не менялись.

Notes Cards v1 объединён с `main` через Pull Request #32. Этап меняет только визуальный слой «Знания → Заметки» и UI-guard от универсального collapse:

- карточки заметок должны быть раскрыты сразу;
- название и текст заметки получают приоритет;
- `Изменить / Удалить` не должны мешать содержимому;
- на узком экране сетка становится одноколоночной;
- `app.js`, данные заметок, Data Store и обработчики не менялись.

---

# 4. Принятые решения

- исправлять подтверждённую причину, а не маскировать симптом;
- избегать вложенной вертикальной прокрутки там, где экран может расти в обычном потоке страницы;
- не дублировать существующую бизнес-логику;
- универсальный collapse не должен скрывать ключевые пользовательские карточки;
- текст и содержимое записи важнее технических действий;
- данные и Data Store не менять для чисто визуальных этапов;
- после завершения раздела «Жизнь» последовательно дорабатывать раздел «Знания».

# 7. Что пока не менять

Без отдельной причины не менять:

- пользовательские данные;
- Data Store и формат `localStorage`;
- `core/models/task.js`;
- календарную и проектную бизнес-логику;
- автоматические связанные задачи;
- route id;
- импорт и экспорт;
- уже принятые экраны планирования, проектов и раздела «Жизнь».
