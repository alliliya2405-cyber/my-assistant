# 4. Принятые решения

- раздел «Проекты» дорабатывать по одному экрану и принимать каждый шаг отдельно;
- исправлять причину, а не маскировать симптом;
- данные и Data Store не менять для чисто визуальных этапов;
- не продолжать полировку уже удобного состояния без конкретной пользовательской проблемы;
- верх ресурсной карты должен быстро давать сводку, но не отнимать слишком много места у главной рабочей части — карточек сотрудников;
- четыре сводных показателя и их кликабельность сохраняются, меняется только плотность отображения;
- после подтверждения верхней зоны следующий UX-фокус — читаемость самих карточек сотрудников, прежде всего различимость нагрузки, метрик, ближайшего срока, проектов и поручений.

# 7. Что пока не менять

Без отдельной продуктовой причины не менять:

- пользовательские данные;
- Data Store и формат `localStorage`;
- `core/models/task.js`;
- `app.js`;
- проектную и календарную бизнес-логику;
- автоматические связанные задачи;
- route id;
- завершённые экраны «Совещания», «Все проекты» и «Команда»;
- расчёт нагрузки и правила определения просроченных поручений;
- содержимое и действия карточек сотрудников;
- «Отчёты» до их отдельного этапа.
