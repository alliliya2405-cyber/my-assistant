# 4. Принятые решения

- раздел «Проекты» дорабатывать по одному экрану и принимать каждый шаг отдельно;
- исправлять причину, а не маскировать симптом;
- данные и Data Store не менять для чисто визуальных этапов;
- не продолжать полировку уже удобного состояния без конкретной пользовательской проблемы;
- на экране «Команда» верхние действия и пояснения воспринимаются как единый управляющий блок;
- внутри карточки участника визуально разделять данные человека, участие в проектах и поручения;
- форму поручения улучшать отдельно от бизнес-логики поручений;
- строка «участие в проектах» показывается только при реальной проектной привязке: участник проекта/подпроекта либо поручение с конкретным `projectId`;
- поручение «Без проекта» само по себе не должно создавать ложную проектную привязку;
- участие человека в совещании используется для сопоставления личности и не должно автоматически превращаться в членство в проектной команде.

# 5. Над чем работаем сейчас

Текущий рабочий экран — **«Проекты → Команда»**.

Визуальная часть экрана после трёх этапов завершена.

Также выполнена отдельная кодовая проверка ранее замеченного случая, когда у отдельных карточек (например, участников с поручениями «Без проекта») нет строки участия в проектах.

Проверка показала, что это соответствует текущей модели данных:

- `teamRegistry()` добавляет проектную строку для реального участника проекта/подпроекта;
- для поручения проектная строка добавляется только если у поручения есть существующий `projectId`;
- поручения «Без проекта» оставляют человека в едином реестре, но не создают фиктивную проектную роль;
- модуль сопоставления участников совещаний (`meeting-team-directory-v1.js`) помогает объединять одно и то же лицо по имени/инициалам, но не добавляет членство в проект автоматически;
- `team-registry-identity-v1.js` сохраняет и объединяет уже существующие реальные проектные строки, не создавая новые из directory metadata.

Поэтому отдельное исправление логики для отсутствующих строк проекта сейчас **не требуется**: изменение привело бы к смешению «участник совещания / получатель поручения» и «член проектной команды».

Экран **«Проекты → Команда» можно считать завершённым на текущем уровне продукта**.

Следующий рабочий экран по принятой очереди — **«Проекты → Ресурсная карта»**.

Рабочая версия: `main`.

# 7. Что пока не менять

Без отдельной продуктовой причины не менять:

- пользовательские данные;
- Data Store и формат `localStorage`;
- `core/models/task.js`;
- `app.js`;
- проектную и календарную бизнес-логику;
- автоматические связанные задачи;
- route id;
- завершённые экраны «Совещания», «Все проекты» и «Команда»;
- семантику проектного членства: совещание или поручение без проекта не считать членством в проекте;
- «Отчёты» до их отдельного этапа.
