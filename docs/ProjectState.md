# 1. Что это за проект

«Мой ассистент» — персональный цифровой планнер и цифровой ассистент для ежедневной работы с задачами, проектами, планированием, знаниями и личными областями жизни.

Проект развивается небольшими законченными этапами с обязательной проверкой и защитой пользовательских данных.

---

# 2. Стабильная версия

Стабильная контрольная версия находится в ветке `main`.

В `main` находятся:

- Architecture v2;
- единая модель задачи `core/models/task.js`;
- Data Model v1;
- Data Store Design v1;
- `core/storage/data-store.js`;
- начальное чтение через `MyAssistantDataStore.load()`;
- обычное сохранение через `MyAssistantDataStore.save(state)`;
- cache-busting `app.js?v=18` после изменения механизма сохранения.

---

# 3. Что завершено и проверено

Этап Data Store save v1 завершён.

Проверено автоматически:

- синтаксис `app.js` и `core/storage/data-store.js`;
- точечный diff `persist(...)`;
- roundtrip `save() → load()`;
- сохранение прежнего JSON-формата;
- повторное сохранение изменённого объекта;
- отсутствие временных workflow в итоговом diff.

Проверено пользователем на опубликованной версии:

- существующие задачи и проекты сохранились после перевода чтения на Data Store;
- новая/изменённая задача сохраняется после перезагрузки страницы после перевода `persist(...)` на Data Store.

Дополнительно обнаружена и исправлена ошибка публикационного контроля: после изменения `app.js` в `index.html` оставался старый параметр `app.js?v=17`. Он обновлён до `v=18`, чтобы браузер гарантированно получал актуальный код.

Технический фундамент чтения и обычного сохранения считается проверенным.

---

# 4. Принятые решения

- дальнейший рефакторинг Data Store не является текущим приоритетом;
- импорт, экспорт и резервная копия импорта пока остаются по прежней схеме и меняются только при реальной необходимости;
- ключ `myAssistantProFinal.v1` и формат пользовательских данных не меняются;
- следующий большой этап — Application UX / Structure v1;
- перед визуальной переработкой сначала проектируется информационная архитектура приложения;
- существующие функции на первом UX-этапе не удаляются и данные не мигрируют.

---

# 5. Над чем работаем сейчас

Начат этап **Application UX / Structure v1**.

Рабочая ветка:

`application-ux-structure-v1`

Первый объект анализа — текущая боковая навигация и структура экранов.

В текущем приложении 23 пункта основного меню в группах «Сегодня», «Работа», «Жизнь», «Знания», «Система». Ежедневные функции и редкие сервисные действия находятся почти на одном уровне, поэтому меню перегружено.

В рабочей ветке создаётся `docs/ApplicationUXStructure.md` с предложением новой информационной архитектуры без изменения кода интерфейса.

---

# 6. Следующее одно действие

**проверить и утвердить предлагаемую структуру из `docs/ApplicationUXStructure.md` перед изменением навигации в коде.**

После утверждения первым кодовым шагом будет только новая структура боковой навигации при сохранении существующих route id и render-функций.

---

# 7. Что пока не менять

Пока не менять:

- пользовательские данные;
- Data Store и формат `localStorage`;
- `core/models/task.js`;
- существующие render-функции экранов;
- route id;
- бизнес-логику задач, проектов и календарей;
- импорт и экспорт;
- визуальный дизайн карточек и форм;
- цвета и общую дизайн-систему.

---

# 8. Что отложено на потом

После утверждения структуры приложения:

- реализовать более понятную боковую навигацию;
- проверить доступность всех старых экранов;
- затем отдельно проектировать Главную/Сегодня;
- затем постепенно улучшать визуальный дизайн и удобство экранов.

Отдельно по необходимости:

- перевод резервной копии импорта на Data Store;
- проверка импорта и восстановления;
- сервер, синхронизация между устройствами и другие инфраструктурные функции только при появлении реальной потребности.
