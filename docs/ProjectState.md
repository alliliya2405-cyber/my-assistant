# 4. Что проверено

Перед проектированием проверена фактическая работа хранения в `app.js`.

Подтверждено:

- основной ключ данных — `myAssistantProFinal.v1`;
- приложение при запуске читает JSON напрямую из `localStorage`;
- сохранение выполняется через текущую функцию `persist(...)`;
- перед импортом используется резервная копия `myAssistantProFinal.v1.beforeImport`;
- существующая функция `normalize(...)` отвечает за совместимость структуры данных;
- текущий механизм работает и не должен быть изменён одновременно с проектированием нового слоя.

`docs/DataStoreDesign.md` описывает слой без изменения формата данных и без миграции.

---

# 5. Принятые решения

- Новый слой сначала остаётся поверх текущего `localStorage`.
- Основной ключ `myAssistantProFinal.v1` не меняется.
- Формат JSON не меняется только ради нового слоя.
- Новый модуль предлагается разместить в `core/storage/data-store.js`.
- Минимальный интерфейс v1: `load()`, `save(data)`, `saveBackup(name, data)`, `loadBackup(name)`.
- Data Store отвечает только за физическое чтение и запись, а не за UI.
- `normalize(...)` и `sample()` пока остаются вне Data Store.
- Не вводятся заранее отдельные Repository для каждой сущности.
- Пользовательские данные нельзя очищать или мигрировать без отдельной необходимости и проверки.

# 9. Что отложено на потом

После объединения проекта Data Store можно выполнять отдельными этапами:

- реализацию `core/storage/data-store.js`;
- подключение Data Store к существующей загрузке и `persist(...)`;
- перевод резервной копии импорта на Data Store;
- пользовательскую проверку сохранения, перезагрузки, экспорта и импорта;
- дальнейшее выделение сервисов или Repository только при реальной необходимости;
- синхронизацию между устройствами;
- серверное хранение при появлении реальной потребности.
