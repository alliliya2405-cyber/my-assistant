# 4. Принятые решения

- проект развивается по одному небольшому завершённому шагу;
- исправлять причину, а не маскировать симптом;
- данные и Data Store не менять для чисто визуальных этапов;
- не продолжать полировку уже удобного состояния без конкретной пользовательской проблемы;
- завершённые экраны больше не менять без отдельной причины;
- перед фиксацией первой итоговой версии выполнить **Final Product Audit v1**, а не начинать новый цикл косметической доработки;
- релизный аудит должен включать автоматическую проверку синтаксиса, существующих регрессионных тестов и подключаемых ресурсов;
- найденные в финальном аудите дефекты исправлять минимально и сразу повторно прогонять общий regression workflow;
- после технического аудита отдельно выполнить пользовательский smoke-test сохранения и основных ежедневных сценариев;
- сервер и синхронизация между устройствами не являются условием первой итоговой версии.
