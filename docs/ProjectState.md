# 1. Что это за проект

«Мой ассистент» — персональный цифровой планнер и цифровой ассистент для ежедневной работы с задачами, проектами, планированием, знаниями и личными областями жизни.

Проект развивается небольшими законченными этапами с обязательной проверкой и защитой пользовательских данных.

---

# 2. Стабильная версия

Стабильная контрольная версия находится в ветке `main`.

В `main` находятся Architecture v2, Data Model v1, Data Store v1, Application UX navigation v1 и обновлённый пользовательский интерфейс основных разделов приложения.

Визуально подтверждены пользователем:

- «Главная»;
- «Задачи»;
- «Проекты»;
- «Сегодня»;
- «Неделя»;
- «Месяц»;
- весь раздел «Жизнь»;
- весь раздел «Знания»;
- «Ещё → Поиск» — пустое состояние и реальные результаты поиска.

---

# 3. Что завершено и проверено

Основные пользовательские разделы доведены до единой спокойной визуальной системы.

Раздел «Жизнь» завершён и визуально подтверждён пользователем.

Раздел «Знания» завершён и визуально подтверждён пользователем.

«Ещё → Поиск» завершён и подтверждён пользователем: поиск работает, результаты читаются отдельными карточками.

Для оставшихся служебных экранов выполнен автономный финальный UI-проход без изменения бизнес-логики:

- «Хронология» — подготовлена обычная вертикальная лента без универсального collapse и дублирующих шапок;
- «Настройки и шаблоны» — разделены обычные действия и опасная зона очистки примеров, улучшена адаптивность списка шаблонов;
- «Обмен календарём» — визуально разделены направления «из приложения / в приложение», список будущих задач упорядочен;
- универсальный collapse адресно отключается на этих служебных экранах.

При этих изменениях не менялись `app.js`, пользовательские данные, Data Store, модель задач, алгоритм поиска, импорт/экспорт и календарная бизнес-логика.

---

# 4. Принятые решения

- исправлять подтверждённую причину, а не маскировать симптом;
- избегать вложенной вертикальной прокрутки там, где экран может расти в обычном потоке страницы;
- универсальный collapse не должен скрывать ключевой контент и не нужен на простых служебных экранах;
- текст и содержимое важнее технических действий;
- данные и Data Store не менять для чисто визуальных этапов;
- опасные действия визуально отделять от обычных;
- пользователь не должен вручную участвовать в каждом промежуточном шаге: ИИ выполняет доступную разработку самостоятельно, а пользователь принимает итоговую контрольную версию.

# 7. Что пока не менять

Без отдельной продуктовой причины не менять:

- пользовательские данные;
- Data Store и формат `localStorage`;
- `core/models/task.js`;
- календарную и проектную бизнес-логику;
- автоматические связанные задачи;
- route id;
- алгоритм глобального поиска;
- уже принятые экраны планирования, проектов, «Жизни» и «Знаний».

---

# 8. Что отложено на потом

После финальной UI-приёмки отдельно рассмотреть:

- перенос импорта/экспорта из нижней части меню в «Настройки и шаблоны»;
- функциональные улучшения, которые выявятся при ежедневном использовании;
- сервер и синхронизацию между устройствами — только при реальной потребности.
