# 5. Принятые решения

- Новый слой сначала работает поверх текущего `localStorage`.
- Основной ключ `myAssistantProFinal.v1` не меняется.
- Формат JSON не меняется только ради нового слоя.
- Новый модуль должен находиться в `core/storage/data-store.js`.
- Минимальный интерфейс v1: `load()`, `save(data)`, `saveBackup(name, data)`, `loadBackup(name)`.
- Data Store отвечает только за физическое чтение и запись, а не за UI.
- `normalize(...)` и `sample()` пока остаются вне Data Store.
- Отдельные Repository для каждой сущности заранее не вводятся.
- Пользовательские данные нельзя очищать или мигрировать без отдельной необходимости и проверки.

# 8. Что пока не менять

Пока не менять без отдельного решения:

- существующий работающий интерфейс;
- прикладную логику, не относящуюся к подключению Data Store;
- основной ключ `myAssistantProFinal.v1`;
- формат и содержимое существующего `localStorage`;
- функцию `normalize(...)`;
- стабильную модель задач `core/models/task.js`;
- пользовательские данные;
- способ хостинга приложения.

На следующем этапе сначала создаётся сам модуль Data Store. Подключение всех мест приложения к нему выполняется только после проверки модуля.

---

# 9. Что отложено на потом

После создания и проверки модуля Data Store можно выполнять отдельными этапами:

- подключение Data Store к начальной загрузке приложения;
- перевод `persist(...)` на `DataStore.save(state)`;
- перевод резервной копии импорта на Data Store;
- пользовательскую проверку сохранения, перезагрузки, экспорта и импорта;
- дальнейшее выделение сервисов или Repository только при реальной необходимости;
- синхронизацию между устройствами;
- серверное хранение при появлении реальной потребности.
