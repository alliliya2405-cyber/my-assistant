# 1. Что это за проект

«Мой ассистент» — персональное веб-приложение для организации задач и дальнейшего развития функций личного цифрового ассистента.

Проект развивается небольшими законченными этапами без переписывания работающих частей без необходимости.

---

# 2. Стабильная версия

Стабильная контрольная версия находится в ветке `main`.

В ней внедрена Architecture v2 и единая модель задачи `core/models/task.js`.

Поддерживаются статусы задачи:

- `planned`;
- `done`.

Проверены создание, изменение, завершение, повторное открытие и локальное сохранение задач.

---

# 3. Текущая рабочая ветка

Текущая рабочая ветка:

`data-model-v1`

Ветка предназначена для завершения архитектурного описания модели данных приложения до начала работ над единым слоем хранения.

---

# 4. Что сделано на текущем этапе

Документ `docs/DataModel.md` проверен и доработан.

Исправлены расхождения между первоначальным описанием и стабильным кодом приложения:

- модель `Task` приведена в соответствие с `core/models/task.js`;
- сохранены реальные поля `start`, `duration`, `priority`, `result` и совместимое поле `done`;
- зафиксированы только реально поддерживаемые статусы `planned` и `done`;
- описание `Project` приведено к существующей структуре данных приложения;
- учтены существующие документы `Report / Plan`;
- описаны связи проекта, задач, совещаний, подпроектов и спринтов;
- зафиксировано, что вложенные структуры не нужно преждевременно выделять в отдельные хранилища;
- добавлены правила совместимости и безопасной будущей миграции данных.

Код приложения, интерфейс и текущее `localStorage` на этом этапе не изменялись.

---

# 5. Что проверено

`docs/DataModel.md` повторно прочитан после изменения.

Описание модели задачи сверено со стабильным файлом:

`core/models/task.js`

Описание проекта и документов сверено с существующими структурами данных в `app.js`.

Проверено, что текущий этап является только архитектурной документацией и не требует изменения пользовательских данных или работающего интерфейса.

---

# 6. Принятые решения

- Стабильная модель задачи является исходной точкой для будущего слоя данных, а не заменяется новым несовместимым форматом.
- На текущем этапе используются только статусы задач `planned` и `done`.
- Существующий `localStorage` остаётся действующим механизмом хранения до отдельного этапа.
- Будущий единый слой данных должен сохранять существующие пользовательские данные и совместимость.
- `localStorage` нельзя очищать как способ миграции.
- Подпроекты, спринты, команда и строки отчётов пока могут оставаться вложенными структурами.
- Серверная база данных не добавляется без реальной необходимости.

# 8. Следующее одно действие

Следующее действие:

**подготовить Pull Request `data-model-v1` → `main` для проверки и объединения завершённого описания модели данных.**

После объединения отдельно начать проектирование единого слоя хранения и доступа к данным.

---

# 9. Что пока не менять

Пока не менять без отдельного следующего этапа:

- существующий работающий интерфейс;
- рабочую логику приложения;
- существующий формат и содержимое `localStorage`;
- стабильную модель задач `core/models/task.js`;
- структуру Architecture v2;
- пользовательские данные;
- способ хостинга приложения.

Не начинать реализацию единого хранилища до завершения текущей ветки через Pull Request.

---

# 10. Что отложено на потом

После завершения текущего этапа можно рассматривать:

- единый слой хранения и доступа к данным;
- безопасную миграцию существующего формата при необходимости;
- постепенный перевод разделов приложения на единый слой данных;
- расширение статусов и сущностей только по продуктовой необходимости;
- синхронизацию между устройствами;
- серверное хранение, когда для него появится реальная необходимость;
- дальнейшие функции цифрового ассистента.
