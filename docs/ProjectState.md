# 1. Что это за проект

«Мой ассистент» — персональный цифровой планнер и цифровой ассистент для ежедневной работы с задачами, проектами, планированием, знаниями и личными областями жизни.

# 4. Принятые решения

- раздел «Проекты» дорабатывать по одному экрану и принимать каждый шаг отдельно;
- исправлять причину, а не маскировать симптом;
- данные и Data Store не менять для чисто визуальных этапов;
- не продолжать полировку уже удобного состояния без конкретной пользовательской проблемы;
- экран «Отчёты» показывает основной рабочий сценарий последовательно: персональные документы → сводный документ отдела → работа с готовым документом;
- ручной ввод, импорт, шаблоны и проверка настроек остаются доступными, но визуально не конкурируют с основным сценарием;
- форматы документов, генерацию Word, данные, правила интеграции и существующую бизнес-логику отчётов для визуальных этапов не менять;
- в готовом документе чтение должно иметь больший визуальный приоритет, чем редактирование: заголовок документа и блоки сотрудников читаются первыми, служебные кнопки и действия становятся спокойнее;
- предупреждение распределения времени сохраняется как отдельный значимый контрольный сигнал и не скрывается.

# 5. Над чем работаем сейчас

Текущий рабочий экран — **«Проекты → Отчёты»**.

После подтверждения **Reports Workflow Hierarchy v1** проведён аудит полностью раскрытой карточки готового отчёта.

Выбрана одна конкретная проблема: заголовок, предупреждение, блоки сотрудников, таблицы и кнопки редактирования имеют слишком близкий визуальный вес, поэтому документ воспринимается как большая форма редактирования, а не как документ для чтения.

В `main` выполнен небольшой визуальный этап **Reports Document Reading Hierarchy v1**. Изменён только `styles/reports-workflow-v1.css`:

- шапка готового документа яснее отделена от содержимого;
- служебные действия в шапке стали спокойнее, удаление сохраняет отдельный тревожный стиль;
- каждый сотрудник оформлен как отдельный читаемый блок;
- заголовки сотрудников получили более явный уровень;
- таблицы стали спокойнее: нейтральная шапка, чуть более аккуратные отступы и мягкий hover строки;
- кнопки «Изменить / Удалить» внутри таблиц визуально ослаблены относительно текста документа;
- предупреждение распределения времени сохранено без изменения логики и остаётся заметным;
- данные, строки отчёта, расчёт времени, редактирование, удаление, Word, бизнес-логика и `app.js` не менялись.

Для публикации без старого кэша `styles/reports-workflow-v1.css` подключён как `v=3`.

Рабочая версия: `main`.

# 7. Что пока не менять

Без отдельной продуктовой причины не менять:

- пользовательские данные;
- Data Store и формат `localStorage`;
- `core/models/task.js`;
- `app.js`;
- проектную и календарную бизнес-логику;
- автоматические связанные задачи;
- route id;
- завершённые экраны «Совещания», «Все проекты», «Команда» и «Ресурсная карта»;
- структуру данных отчётов;
- генерацию Word;
- правила импорта CSV/JSON;
- правила формирования сводного документа отдела;
- расчёт и проверку 100% распределения времени;
- подтверждённую верхнюю зону «Шаг 1 → Шаг 2 → Шаг 3» экрана «Отчёты».
