# Контрольное состояние проекта «Мой ассистент»

Обновлено: 15.08.2026
Рабочая инструкция: WORKING-INSTRUCTION-V2.md
Основная ветка: main

## Проект
«Мой ассистент» — локальное приложение для управления жизнью, профессиональными проектами, совещаниями, командой, поручениями, ресурсной картой, отчётами и знаниями. Текущий основной фокус разработки — профессиональный контур дошкольного отдела.

## Текущее устройство
Профессиональный поток данных: проекты → совещания → распознанные и распределённые поручения → карточки команды → ресурсная карта → персональные отчёты/планы → сводные документы дошкольного отдела.

Приложение сейчас хранит данные локально. Основная реализация остаётся в app.js/styles.css с дополнительными модулями и исправлениями в fixes/, core/, styles/ и тестами в tests/. Накопление патчей признано архитектурным риском; при работе в конкретной области разрешён ограниченный рефакторинг без изменения согласованного поведения.

## Проверено и реализовано
- Совещания умеют распознавать задачи и перед распределением дают проверить исполнителя, формулировку, срок и проект.
- Распределённые поручения отображаются в карточках участников команды и сохраняют связь с источником-совещанием.
- В команде поддерживаются карточки участников, роли/участие в проектах, редактирование и удаление участников.
- Ресурсная карта показывает проекты и открытые поручения участников; открытые поручения можно закрывать.
- Профессиональные отчёты отделены от личных задач досуга, здоровья и личного образования.
- Отчёты проверяют распределение времени до 100%; пустой документ считается незаполненным, а не ошибочным — это правило теперь согласовано и с отдельной кнопкой «Проверить настройки».
- Персональные документы: Абдуллина — ручное заполнение или автосборка; Исса и Королева — загрузка готовых документов.
- Сводный документ дошкольного отдела формируется из трёх персональных документов и защищён от сборки из некорректных персональных отчётов.
- Для одного сотрудника и периода действует один персональный документ.
- Повторная валидная загрузка документа Иссы/Королевой за тот же период обновляет существующий документ, а не создаёт дубль; до пяти предыдущих версий строк сохраняются внутри документа в previousVersions.
- Кодовый аудит report workflow после PR #58–#63 выявил и исправил несогласованность пустых черновиков и повторных импортов; добавлен регрессионный тест.
- Последний функциональный main: 1138d80 — Stabilize report audit and repeated imports (#64).

## Принятые решения
1. Пользователь определяет продукт; техническую реализацию ChatGPT ведёт самостоятельно.
2. GitHub/main — источник технической истины.
3. Исправляется класс проблемы, а не только показанный экземпляр.
4. Перед сообщением о готовности обязательна самопроверка и проверка связанных сценариев.
5. «Готово» = реализовано + технически проверено + связанные сценарии проверены + находится в main. Подтверждение пользователя — отдельный статус.
6. Старые данные нельзя удалять только потому, что они выглядят тестовыми или устаревшими; безопасная миграция без потери данных разрешена.
7. Небольшие очевидные побочные ошибки исправляются самостоятельно.
8. После короткого шага работа автоматически продолжается внутри текущего направления.
9. Профессиональные отчёты не включают личные области.
10. В заполненном отчёте распределение времени сотрудника должно составлять ровно 100%.
11. Сводный документ отдела строится из персональных документов Абдуллиной, Исса и Королевой за соответствующий период.
12. Повторный импорт персонального документа за тот же период должен обновлять единственный рабочий документ без потери предыдущей версии.

Продолжить аудит перекрывающихся report fixes: проверить взаимодействие базового reports-personal-department-v1.js с отдельными слоями import-validation, department-integration-guard и single-personal-document. Следующая цель — убрать дублирующиеся обработчики там, где это можно сделать безопасно, сохранив текущий интерфейс и существующие локальные данные.

## Не менять сейчас
- Общую концепцию навигации приложения.
- Согласованную цепочку проектов/совещаний/поручений/команды/ресурсной карты.
- Правило отделения профессиональных данных от личных.
- Персонально-сводную модель отчётов.
- Рабочие функции команды и ресурсной карты без обнаруженной регрессии.

## Отложено
- Более крупный архитектурный перенос приложения с локального хранения на сервер/БД.
- Авторизация и реальные многопользовательские сценарии.
- Хостинг/несколько сред/CI-CD как отдельный этап, если они понадобятся.
- Глубокий рефакторинг всего app.js вне затронутой текущим направлением области.

## Известные риски
- В report workflow ещё остаются несколько последовательных fixes, часть которых перехватывает одни и те же пользовательские события; порядок загрузки пока важен.
- Существующие локальные данные пользователя могли быть созданы до последних миграций и должны проверяться отдельно от новых данных.
- previousVersions сейчас является внутренним резервом данных и ещё не имеет пользовательского интерфейса восстановления.
- UI-проверка пользователем остаётся важной для визуальных решений, даже после технических тестов.
