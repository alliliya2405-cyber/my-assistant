# Project

Модель проекта в приложении «Мой ассистент».

## Назначение

Project — центральная сущность профессиональной части приложения.

С проектом могут быть связаны:

- подпроекты;
- спринты;
- задачи;
- участники;
- совещания;
- дорожная карта;
- бизнес-процесс;
- документы;
- артефакты;
- отчёты;
- риски;
- контрольные точки;
- история изменений.

## Основные поля

### Идентификация

- `id` — уникальный идентификатор проекта;
- `name` — название проекта;
- `description` — краткое описание;
- `goal` — цель проекта;
- `meaning` — смысл или ценность проекта.

### Сроки

- `startDate` — плановая дата начала;
- `endDate` — плановая дата завершения;
- `actualStartDate` — фактическая дата начала;
- `actualEndDate` — фактическая дата завершения.

Внутренний формат дат:

`YYYY-MM-DD`

Пользовательский формат отображения:

`ДД.ММ.ГГГГ`

### Управление

- `status` — статус проекта;
- `priority` — приоритет;
- `progress` — процент выполнения;
- `ownerId` — руководитель проекта.

Рекомендуемые статусы:

- planned
- active
- paused
- completed
- archived

### Классификация

- `areaIds` — направления, к которым относится проект;
- `tagIds` — теги проекта.

Один проект может относиться сразу к нескольким направлениям.

## Связи

Project не должен хранить полные копии связанных объектов.

Связи строятся по устойчивым идентификаторам.

Например:

- Subproject содержит `projectId`;
- Sprint содержит `projectId`;
- Task содержит `projectId`;
- Meeting содержит `projectIds`;
- ProjectMember содержит `projectId`;
- Artifact содержит `projectId`.

Это позволяет одной задаче или совещанию отображаться в нескольких разделах без дублирования данных.

## Команда

Команда проекта формируется автоматически из:

- прямых участников проекта;
- участников подпроектов;
- ответственных за задачи;
- ответственных за спринты.

Участник не должен дублироваться в общей команде проекта.

## Подпроекты

Проект может содержать неограниченное количество подпроектов.

Подпроекты являются отдельными сущностями и связываются с проектом через `projectId`.

## Спринты

Спринт может относиться:

- непосредственно к проекту;
- к подпроекту внутри проекта.

## Дорожная карта

Дорожная карта проекта формируется из:

- даты начала и завершения проекта;
- подпроектов;
- спринтов;
- задач;
- контрольных точек;
- совещаний;
- артефактов.

Дорожная карта не должна хранить отдельную копию этих данных.

Она является представлением уже существующих сущностей.

## Прогресс проекта

Прогресс должен вычисляться на основании связанных задач, спринтов и контрольных точек.

Ручное изменение прогресса допускается только как специальная настройка.

## История

Изменения проекта должны фиксироваться в истории:

- создание;
- изменение сроков;
- изменение статуса;
- добавление участника;
- изменение команды;
- создание подпроекта;
- завершение спринта;
- изменение приоритета;
- архивирование.

## Архив

Удаление проекта не должно сразу уничтожать его данные.

Сначала проект переводится в архив.

Для этого используется:

- `archivedAt`

Полное удаление — отдельное подтверждаемое действие.

## Технические поля

Каждый проект должен иметь:

- `createdAt`
- `updatedAt`
- `archivedAt`

В будущем для синхронизации также понадобятся:

- `version`
- `syncStatus`

## Главное правило

Project является источником истины только для собственных данных проекта.

Задачи, участники, совещания, документы и спринты должны храниться как отдельные сущности и связываться с проектом через ID.
